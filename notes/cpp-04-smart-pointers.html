學習目標

  • 能夠依所有權語意選擇 unique_ptr、shared_ptr 或 weak_ptr
  • 能夠解釋 shared_ptr 循環參照造成的記憶體洩漏，並以 weak_ptr 解決
  • 能夠避免以同一個原始指標建立多個智慧指標

核心概念

所有權的語意

在設計介面時，先決定誰擁有物件。獨佔所有權使用 std::unique_ptr，它不可拷貝、只能移動，釋放時機明確。需要共享所有權時使用 std::shared_ptr，內部以參考計數決定何時釋放。只需觀察而不影響生命週期時，使用原始指標或參考即可。

make_unique 與 make_shared

優先使用 std::make_unique（C++14）與 std::make_shared。後者通常只需一次記憶體配置，且避免在複雜運算式中因求值順序而洩漏資源。

循環參照與 weak_ptr

若兩個物件互相持有對方的 shared_ptr，參考計數永遠不會歸零，兩者都無法被釋放。std::weak_ptr 觀察物件但不增加參考計數，需要存取時以 lock() 取得暫時的 shared_ptr。

程式範例

編譯指令：g++ -std=c++17 -Wall -Wextra main.cpp

範例 1：獨佔所有權與共享所有權

#include <iostream>
#include <memory>

int main() {
    auto u = std::make_unique<int>(42);     // 獨佔
    // auto u2 = u;                          // 編譯錯誤：unique_ptr 不可拷貝
    auto u2 = std::move(u);                 // 所有權轉移，u 變為 nullptr

    auto s1 = std::make_shared<int>(7);    // 共享
    auto s2 = s1;                           // 參考計數變為 2
    std::cout << *u2 << ' ' << *s1 << ' ' << s2.use_count() << '\n';
    return 0;
}

預期輸出：

42 7 2

範例 2：以 weak_ptr 打破循環參照

#include <iostream>
#include <memory>

struct Node {
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev;   // 反向連結使用 weak_ptr
    ~Node() { std::cout << "~Node\n"; }
};

int main() {
    auto a = std::make_shared<Node>();
    auto b = std::make_shared<Node>();
    a->next = b;
    b->prev = a;     // 不增加 a 的參考計數
    return 0;         // 兩個 ~Node 都會被呼叫
}

預期輸出：

~Node
~Node

常見錯誤

  • 以同一個原始指標建立兩個 shared_ptr：兩者各自的參考計數都是 1，會造成 double delete。應只從 new 的結果建立一次，或直接使用 make_shared。
  • 循環參照：如範例中若將 prev 也改為 shared_ptr，兩個 Node 都不會被釋放，且不會有任何錯誤訊息。
  • 從 get() 取得的原始指標被長期保存：當智慧指標被銷毀後，該指標即為懸空指標。

課堂練習

練習 1：為何 std::unique_ptr 可以被放入 std::vector，但不能被拷貝到另一個 unique_ptr？

std::vector 在重新配置時會搬移元素，此時移動即足夠；而拷貝建構子被刪除，代表不允許兩個 unique_ptr 同時擁有同一物件。

練習 2：將範例 2 的 prev 改為 shared_ptr，預測輸出並說明原因

輸出將不再有任何 ~Node。a 與 b 互相持有對方，參考計數永遠大於 0，形成循環參照。
